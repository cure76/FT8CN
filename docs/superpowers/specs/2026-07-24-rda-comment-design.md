# RDA в COMMENT QSO — спецификация дизайна

**Дата:** 2026-07-24  
**Статус:** утверждено; пилот реализован в коде  
**Форк:** FT8CN-RN3AOE (`com.rn3aoe.ft8cn`)  
**Связано:** автообновление сетки (активный GPS), экспорт ADIF через `COMMENT`

---

## 1. Цель

При завершении QSO, если включён **Auto grid**, в поле ADIF `COMMENT` дописывать код **своего** района RDA (снимок на старте QSO), чтобы в мобильном логе было видно, из какого района РФ проведена связь.

Пример:

```text
Distance: 1089 km, RDA: MO-52, QSO by FT8CN
```

Если район определить нельзя — сегмент `RDA: …` **не** пишем (формат comment как сейчас).

---

## 2. Принятые решения

| Тема | Решение |
|------|---------|
| Куда писать | Только `COMMENT` (в пилоте без новых полей ADIF / колонок БД) |
| Покрытие пилота | Москва + Московская область (МО) |
| Расширение | Пакеты по регионам; другие области позже без смены архитектуры |
| Момент снимка | **Старт QSO** (как `myMaidenGridAtStart`) |
| UI | В пилоте нет (текущий RDA на экране не показываем) |
| Координаты | Только при включённом **Auto grid** (активный GPS) |
| Движок | Офлайн GeoJSON (или аналог) + point-in-polygon |

- Отображение текущего RDA в настройках / UI

- RDA **корреспондента** (только **свой** RDA)  
- Определение RDA при выключенном Auto grid

## 4. Архитектура

```text
Фикс GPS (Auto grid)
    → обновить lastKnown LatLng (+ Maidenhead как сейчас)
    → (опционально) кэшировать последний код RDA

Старт QSO (порядок сообщений 1/2)
    → myMaidenGridAtStart = сетка
    → myRdaAtStart = lookup(lastKnownLatLng)  // или "" если нет

Успешная QSO → QSLRecord.comment
    → "Distance: …, RDA: XX-NN, QSO by FT8CN"  // если myRdaAtStart не пустой
    → иначе прежний "Distance: …, QSO by FT8CN" / "QSO by FT8CN"

Экспорт ADIF
    → COMMENT уже пишется из БД; меняется только содержимое строки
```

### Компоненты

| Компонент | Назначение |
|-----------|------------|
| `GeneralVariables` (или небольшой holder) | Последние lat/lon при Auto grid; опционально последний RDA |
| `RdaLookup` (новый) | Загрузка пакетов регионов, point-in-polygon → `rda_code` |
| Assets регионов | `assets/rda/*.geojson` (+ индекс пакетов) |
| `MainActivity` (GPS) | При обновлении координат — сохранить lat/lon; опционально обновить кэш RDA |
| `FT8TransmitSignal` | Снимок `myRdaAtStart` вместе с сеткой на старте QSO |
| Конструктор `QSLRecord` | Опциональный RDA и формирование COMMENT |

## 5. Формат данных (пакеты регионов)

### Структура (пилот)

```text
ft8cn/app/src/main/assets/rda/
  index.json              # список включённых пакетов
  mo_moscow.geojson       # Москва + МО (имя файла уточняется)
```

### `index.json` (пример)

```json
{
  "version": 1,
  "packs": [
    { "id": "mo_moscow", "file": "mo_moscow.geojson", "enabled": true }
  ]
}
```

### Свойства Feature (обязательно)

У каждого полигона:

- `rda_code` — строка, например `"MO-52"`, `"MA-01"` (коды из официального списка RDA)

Опционально: `name` / `name_ru` для отладки (в COMMENT в пилоте не пишем).

### Геометрия

- Polygon / MultiPolygon, WGS84  
- Упрощённая геометрия (баланс размера APK и точности границ)  
- Сопоставление названий OSM/админки с кодами RDA — отдельный этап подготовки данных; ошибка маппинга = ошибка в логе

### Расширение позже

1. Добавить файл, например `spb_lo.geojson`  
2. Зарегистрировать в `index.json` с `"enabled": true`  
3. Java API не менять, если `RdaLookup` грузит все включённые пакеты

## 6. Поведение lookup

1. Auto grid **выкл** → координаты для RDA не ведём → `myRdaAtStart = ""`  
2. Auto grid **вкл**, но фикса ещё нет → `""`  
3. Точка вне загруженных пакетов → `""`  
4. Точка внутри полигона → `rda_code` этого Feature  
5. Граница / несколько попаданий: первый совпавший Feature в порядке данных; для города vs области порядок полигонов в пакете нужно продумать при подготовке данных  

Производительность: для пилотного объёма достаточно линейного перебора. Позже — bbox / индекс при необходимости.

---

## 7. Правила формата COMMENT

Сейчас:

```text
Distance: {dist}, QSO by FT8CN
```
или
```text
QSO by FT8CN
```

С RDA (только если код не пустой):

```text
Distance: {dist}, RDA: {code}, QSO by FT8CN
```
или (без дистанции):

```text
RDA: {code}, QSO by FT8CN
```

Коды не выдумывать; `RDA: unknown` не писать.

## 8. Точки интеграции в коде

1. **GPS (`MainActivity`)** — при обновлении локации для Auto grid сохранять `lastLat` / `lastLon` (и опционально кэш RDA).  
2. **Старт QSO (`FT8TransmitSignal`)** — вместе с `myMaidenGridAtStart` выставлять `myRdaAtStart`.  
3. **`QSLRecord(...)`** — опциональный параметр RDA при сборке `comment`.  
4. **Сброс снимка** — очищать `myRdaAtStart` там же, где сбрасывается снимок сетки.

`ShareLogs` / INSERT в `QSLTable` менять не нужно, если RDA живёт только внутри строки `comment`.

## 10. Риски

| Риск | Смягчение |
|------|-----------|
| Неверный маппинг OSM→RDA | Проверка известных точек до релиза |
| Большой GeoJSON | Упрощение геометрии; при росте APK — компактный формат |
| Спорная граница | Первый match; задокументировать; уточнить порядок в пакете |
| Auto grid выкл | В comment нет RDA (по задумке) |
| Нет свежего GPS | Снимок того, что есть на старте QSO; иначе пусто |

---

## 11. План проверки (пилот)

1. Auto grid ON, известный район Москвы → QSO → в COMMENT есть `RDA: MA-xx`.  
2. Auto grid ON, район МО → `RDA: MO-xx`.  
3. Auto grid OFF → в COMMENT нет `RDA:`.  
4. Auto grid ON без фикса → нет `RDA:`.  
5. Точка вне Москва+МО (мок) → нет `RDA:`.  
6. Поведение `my_gridsquare` (6 символов) и дистанции не ломается.
